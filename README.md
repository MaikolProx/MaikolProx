## Validadores de empleo (lo que busca un hiring manager en 2026)

**1. Prueba de trabajo visible, no badges.** El candidato con GitHub público organizado y UN proyecto del que pueda hablar 10 minutos gana al de la hoja llena de certificados. Un repo medio-terminado con README limpio supera a los screenshot de badges.

**2. Evales con números.** "Recall@5 0.62 → 0.75 (+19%) con reranking", "NDCG@5 0.90", "faithfulness 94%" — eso es lo que separa un demo de un sistema. Todos mis proyectos tienen `evals/` con métricas nombradas y before/after.

**3. Plataformas de práctica (TryHackMe / HTB / KC7 / Kusto).** TryHackMe Top 5-10% con learning path completado (Junior Penetration Tester) muestra compromiso de aprendizaje; perfil público de HackTheBox con máquinas resueltas muestra skill independiente. **KC7 Cyber (KQL + threat hunting mindset) es un diferenciador raro** — casi nadie lo pone en el CV y es el perfil que más escasea en SOC. La combinación ganadora: **plataformas + certificación** (Security+ → eJPT → OSCP) + write-ups con metodología.

**4. Certificaciones.** Abren la puerta del ATS/RRHH (los postings los escribe RRHH; el CV no llega al hiring manager sin pasar ese filtro), pero **no demuestran capacidad** — la prueba de trabajo sí. Security+ primero (método gratis probado: Professor Messer + objetivos oficiales CompTIA); eJPT y OSCP pesan en consultoría de pentesting (OSCP en ~70% de postings). CISSP (vía FRSecure + libro oficial) cuando se cumplan los requisitos de experiencia.

**5. Write-ups y capacidad de comunicar.** 600 palabras: qué construí, por qué, qué se rompió, qué arreglé. El README es la audición: demuestra si puedes documentar un hallazgo o pasar un ticket.

**6. Contribución open source.** Un PR mergeado (aunque sea pequeño) a LangChain/LlamaIndex/Ragas/vLLM vale más que otro proyecto desde cero: prueba que navegas un codebase real y sobrevives review de maintainers.
